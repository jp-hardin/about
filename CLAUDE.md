# Notes for Claude Code

- Site pages under `mid-market-practice/` are generated by `mid-market-practice/_build/build.py`. Edit the script and rerun it; do not hand-edit the generated HTML.
- Industry reports live in `mid-market-practice/insights/` as `<industry>-industry-report-q<N>-<year>.html/.pdf` and are generated from `mid-market-practice/_build/reports/<report>/`. See the README in each report folder for the rebuild command. All five (Industrial, Business Services, Consumer, Healthcare and Technology) are built from the PowerPoint report deck in the folder (`brief.pptx`, the authoritative source) by `_build/reports/brief.py`, so the PDF and the page always match: change the deck and rerun `sh build.sh`, never the generated page. The site's top level is Industries (the five above, under `industries/`); the level below is Sectors. `REPORTS_LIVE` in `_build/build.py` (set from the `MMT_REPORTS` environment variable: on by default for the github.io preview, off for the live preview and live copy unless the Stage live preview workflow is run with reports "shown") switches the reports on or off; while False it hides the Insights page, report pages, PDFs and every link to them (and the report builder refuses to run without `--preview`). The Q4 2026 decks are the final versions with the house fixes applied in the deck itself (Jordan's transaction wording, Industrials, Middle Market, serial commas, Jason Lisiak, CFA, the valuations disclosure line, logo alt text), so the deck, PDF and page match. The web page is laid out for the web, not as slides (`webdeck.py` `web()`): the slides only supply reading order and grouping; side-by-side content becomes a responsive grid, logos become company names, aligned text becomes tables, transaction tiles become deal cards, and notes and long tables fold away. Use "sector" (not segment or focus area) for the level below an industry. Each report page also gets FAQs taken from the deck's own headlines (`faq.json`, also used in `llms-full.txt`). List each report in `INSIGHTS` in `_build/build.py`; the newest per industry is shown as Current on `insights/index.html` and older ones move to the archive. `reports/` only holds redirects from the old URLs.
- Three stages. (1) Sandbox: merging to `main` ("merge preview") updates the github.io preview at /about/mid-market-practice/ (a bar at the bottom marks it as the sandbox). (2) Live preview ("merge live preview"): run the Stage live preview workflow (`.github/workflows/stage-live-preview.yml`, manual only). It builds main the way it will go live, with the industry reports hidden unless run with reports "shown", marks every page with a red Live preview bar and noindex (`_build/stage.py`), and commits the copy to `live-preview/` on main, served at /about/live-preview/. Never edit `live-preview/` by hand. (3) Live ("merge live"): run the Publish MMT site workflow (`.github/workflows/publish-mmt-site.yml`, manual only) with `ref` main. It strips the marks from `live-preview/` and copies exactly that to jp-hardin/mmt-site, which the mmt.benchmarkintl.com server pulls every 5 minutes, and tags the version `live-<date>-<time>`; to roll back, run it with an earlier `live-*` tag.
- Report PDFs sit behind a short download form (`report_gate()` and `gated()` in `_build/build.py`, `assets/js/main.js`): name, email, two optional opt-ins and agreement to `report-terms.html`. Submissions, a copy of each contact form enquiry and unsubscribes from `email-preferences.html` go to the "MMT Report Downloads" Google Sheet (tabs: All Submissions, General Form, Report Downloads, one per industry) through the Apps Script in `_build/forms/report-signups.gs`; its web app address goes in `REPORT_FORM_URL`. Bump `REPORT_TERMS_VERSION` and `TERMS_UPDATED` when the terms or consent wording change. PDFs are kept out of the sitemap, llms files and robots; the report pages carry the full content.
